InvestorHub — Use Case Diagram

UML 2 · mapped one-to-one to the Express routes and React pages of this repository

Actors (from the code)

  • Guest — no token. GET /api/posts and /api/posts/:id use optionalAuth, so browsing, search / filter and listing details are public; so is the contact form and register / login.
  • Registered User (abstract) — parent of Investor and Businessman, matching User.role. Sign-up creates status: "pending"; the account pays a one-time entry fee and an admin must set status: "active" before requireActive lets the dashboard through.
  • Investor — the only role allowed to fund a listing (checkRole(["investor"]) on POST /api/payments/init).
  • Businessman — publishes business_post listings and receives the funding.
  • Administrator — every /api/admin/* route: user status, listing moderation, reports, payments and entry fees, contact messages, analytics. Admins skip requireActive.
  • SSLCommerz Gateway (external system) — hosts the checkout for both the entry fee and investments; the server re-validates every callback and IPN with the validation API before it marks a payment completed.

Notation & system rules

  • Association — solid line: the actor starts that use case.
  • Generalization — hollow triangle: Investor and Businessman are kinds of Registered User, so they inherit every member use case.
  • «include» — always runs: NID verification includes the image upload (POST /api/upload, the page refuses to submit without a file), managing own listings includes edit / delete, chat includes send message and mark-seen (socket.on("mark_seen")).
  • «extend» — optional: search / filter extends browse, a listing image extends create listing, the invoice PDF extends view my investments, and updating a report status extends reviewing reports.
  • Sign-up sequence in the code: register → pay entry fee → submit NID → /pending → an admin activates the account → dashboard. The columns group use cases by access level, not by order.
  • Chat is only allowed between an investor and a business account (POST /api/conversations); a match request is likewise cross-role.
  • A new listing stays pending until an admin approves it; a completed investment keeps a 10% platform commission, finalizes the match, and flips a fully funded listing to completed.
  • Login and Logout are shared by every role; only the Guest and member associations are drawn so the actor lines stay readable.
