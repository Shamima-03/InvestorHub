InvestorHub — Use Case Diagram

UML 2 · system boundary, actors, include / extend, and generalization

Actors

  • Guest — not logged in. Can browse public posts, view details, register, and contact support.
  • Registered User — abstract parent. Investor and Businessman inherit all member use cases.
  • Investor / Businessman — after admin approval (status = active) they can post, match, and chat. Chat is only allowed between opposite roles.
  • Administrator — activates accounts, changes status, deletes users, reviews reports, and views analytics.

Write this in the report

  • Association — solid line from an actor to a use case they initiate.
  • Generalization — hollow triangle. Investor and Businessman are kinds of Registered User, so they share member use cases.
  • <<include>> — required extra step. Register always creates a role profile. Chat includes send message and mark seen. Manage posts includes edit/delete.
  • <<extend>> — optional extra step. Search extends browse. Match request can extend view-post. Image upload can extend create-post.
