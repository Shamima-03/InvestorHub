InvestorHub — Data Flow Diagram (DFD)

Level 0 (Context) · Level 1 (Decomposition) · Level 2 (Process Detail)

External entity Process Data store Data flow

Level 0 — Context Diagram

One central process. Each external entity uses two parallel arrows (in and out). Lines are orthogonal and do not cross.

Level 1 — System Decomposition

Processes are stacked in one column. Each process has its own data store on the same row. Entities are duplicated where needed so every connector stays on its row.

Level 2 — Process 1.0 Authentication

Three-column grid. Guest aligns with 1.1; the member entity is repeated on the 1.2 and 1.3 rows.

Level 2 — Process 2.0 Post Management

Member, Guest, and Member (repeated) each sit on their own row. Image upload stays on the 2.1 row, to the right of D3.

Level 2 — Process 3.0 Match Management

Investor is repeated on the 3.1 and 3.2 rows. Businessman sits only on the 3.3 row. Notification back to the investor uses a second Investor box on the right of 3.3.

Level 2 — Process 4.0 Chat Service

Investor and Businessman are each repeated: one copy on the 4.1 row, one copy on the 4.2 row. All flows stay horizontal inside their row.

Level 2 — Process 5.0 Admin Module

Administrator is repeated on each row so approve, moderate, and report-review flows never leave their lane.

Level 0

  • One system process: 0 InvestorHub System.
  • External entities: Guest, Investor, Businessman, Administrator, Image Upload (imgbb).
  • Each entity uses two parallel arrows (in and out). Labels sit beside the arrow, not on top of it.

Level 1

  • Five processes aligned with backend modules: Auth, Posts, Match, Chat, Admin.
  • Six data stores: Users, Profiles, Posts, Matches, Messages, Reports.
  • Entities and D1 are repeated on separate rows so connectors never cross (standard DFD practice).

Level 2

  • 1.0 Register → Login → Manage Profile.
  • 2.0 Create → Browse → Update/Delete post (with imgbb).
  • 3.0 Validate roles → Create request → Accept/Reject.
  • 4.0 Open conversation → Send message (Socket.IO).
  • 5.0 Approve users → Moderate posts → Review reports.
